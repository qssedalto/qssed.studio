## 范围与结论

本轮重点是 TeX 工作台的数据保存、实时协作、文件管理、归档、项目加密聊天和共享登录链路，并执行仓库现有的主站、管理端、搜索、项目、任务、草稿、Cash、Watch、Bridge 接口等回归检查。修复有可复现测试支撑，不以“语法检查通过”代替数据正确性测试。

这是一次有时间边界的代码审计和修复，不是整个平台所有路径、所有浏览器和所有生产网络故障的安全认证。测试通过不等于证明没有任何剩余漏洞。

数据库安全迁移 `20261113154010_oauth_pkce_reject_null_verifier` 已直接应用到生产数据库并完成行为验证。网站代码是否已上线，应以对应 PR 的合并状态和生产部署工作流结果为准，不应把分支测试成功理解为已经部署。

## P0：数据完整性与权限

| 编号 | 问题及风险 | 修复与主要验证 |
|---|---|---|
| P0-01 | 超长或非法源码可能被截断、隐式转换后覆盖正常文件。 | 明确拒绝非法类型、NUL 和超长输入；读取旧文档不静默截断。`tex-p0-integrity-check.mjs` 检查拒绝时零写入。 |
| P0-02 | 主文件保存、附件上传、重命名等重叠请求可能互相覆盖。 | 使用 R2 ETag 条件写；旧客户端必须提交保存基准版本，冲突返回 409/428 而不是覆盖。主文件保存只变更允许字段，保留附件、置顶和锁定信息。 |
| P0-03 | 单独检查协作状态、随后写 R2，中间仍可能插入已确认的新协作更新。 | `/commit-save` 在同一个文档 Durable Object 临界区完成协作验证及 R2 发布；原生入口使用同一契约。`tex-atomic-save-check.mjs` 强制两种并发顺序并验证失败不覆盖。 |
| P0-04 | 过期客户端提交的 Yjs 快照可能覆盖其他人的编辑或复活已删除字符。 | 服务端合并自身快照和更新日志，不信任客户端声称的覆盖序号；拒绝无效二进制和不完整状态。验证删除保留和 75 次多端编辑收敛。 |
| P0-05 | 已确认的乱序 CRDT 更新可能尚不可见，单纯比较可见文本会漏掉它。 | 保存和归档/删除检查 Yjs 待合并结构与删除集合。未解决依赖时拒绝覆盖；完整更新补齐依赖后仍允许正常保存。 |
| P0-06 | 断线重连、初次同步或角色降级可能覆盖本地未保存文本。 | 同项目重连复用原 Y.Doc，保留离线编辑；检测初始冲突，保留本地文本并阻止错误回写；旧连接回调不能关闭新连接。 |
| P0-07 | 删除后仍在途的保存可能使文件重新出现。 | 条件写入不含正文的删除标记，旧 revision/epoch 不能复活文档；撤销旧实时房间。 |
| P0-08 | 归档只检查 R2，可能删除尚未投影到 R2 的已确认协作内容。 | `/commit-retire` 与实时更新共用文档锁；验证快照及未压缩日志与待归档正文一致后才写删除标记。并发、日志、乱序、损坏历史均有回归。 |
| P0-09 | 归档中断、未知提交结果或重置密码并发，可能同时失去明文和密文。 | 归档/重置按账户串行化；先保留密文恢复副本，明确区分条件冲突与未知结果；清理失败可重试，不能虚报完成。覆盖 9 组故障及并发场景。 |
| P0-10 | 归档清理可能遗漏旧协作房间，或误删同房间中无关的加密聊天。 | 记录并清理已知源码 epoch，删除源码快照/日志命名空间，不删除加密消息、封装密钥及 Passkey 记录。 |
| P0-11 | 重命名后的主文件锁、父目录操作可能绕过后代文件锁；原生写入可能丢失附件。 | 各写入入口统一检查主文件及后代锁；共享只读用户不能写；原生保存保留服务器项目元数据。 |
| P0-12 | 附件编辑请求的旧正文可能覆盖另一端已经保存的新正文。 | UTF-8 内容摘要作为附件编辑基准；旧摘要拒绝，但无关主文件编辑不导致误冲突。保存期间继续输入、取消切换和关闭弹窗均保留草稿。 |
| P0-13 | WebSocket 握手或已撤销连接可能继续使用旧权限。 | 严格校验来源，网关重建内部身份头，连接时复核当前项目和权限；先使连接权限过期再关闭，阻止后续广播和写入；房间路由包含源码 epoch。 |
| P0-14 | 项目聊天异步回调、旧轮询、发送结束可能污染新项目状态或清空新草稿。 | 按项目世代隔离异步任务；最新读取优先；发送只清除实际提交过的内容；IndexedDB 事务内重新读取设备身份，避免跨标签页覆盖密钥。 |
| P0-15 | 非所有者聊天发送缺少完整接收者上下文；撤销成员期间存在权限窗口。 | 网关使用当前参与者列表并再次确认成员身份；验证三成员接收者上下文、撤销竞态、CSRF、删除标记以及请求体上限。浏览器使用真实 Web Crypto，但 WebAuthn 硬件调用是测试替身。 |
| P0-16 | PostgreSQL 对 NULL 的比较结果不是 false；缺失 PKCE verifier 可能跳过原来的否定校验。 | 显式拒绝 NULL verifier/challenge，使用 `IS DISTINCT FROM`，要求 S256。生产数据库事务内验证有效交换、空值/错误证明/错误重定向拒绝、单次使用及所有测试记录回滚。 |

主要实现文件包括 `tex-document-guards.js`、`tex-collaboration-save.js`、`tex-collaboration-retire.js`、`tex-collaboration-room.js`、`tex-archive-api.js`、`tex-file-revision.js` 以及相关 API/浏览器运行时代码，均位于 `studio/`。

## P1：稳定性与界面

保存队列使用请求快照判断结果，较早保存完成不会将后续输入标记为已保存，也不会丢弃仍需提交的改动。失败时保留未保存状态和离开提示。共享登录链路将临时网络故障、429、上游 5xx 与确定失效区分，避免上游短暂故障导致无故注销或丢弃已轮换的会话凭据。

工作台标题区根据编辑面板的可用宽度调整布局，不仅依据整个窗口宽度；修复工具栏选择器、窄屏折行和初始化时序等运行时问题。保留既有主题和产品交互，不做无关视觉重设计。

完整生产 Work HTML 与浏览器运行时代码在 Chromium 中验证了 320、390、768、1024、1440、1920 六种宽度、触屏/桌面配置和深浅色模式。检查编辑区可见、页面不横向溢出、顶部控件不互相覆盖、首屏遮罩释放，并运行主文件与附件“请求未完成时继续输入”、取消文件切换、保存失败等流程。

源码 epoch、删除标记和房间隔离解决的是旧数据回流，并不代表已对所有 CDN、Service Worker 或第三方缓存完成专项审计。

## 数据库审计及未覆盖边界

生产数据库复查未发现未开启 RLS 的 public 普通表；anon/authenticated 均不能在 public schema 创建对象，public 中没有需要额外核查的视图。已核对 profiles、协作者、AI 对话、消息、提供商和用量的相关策略，以及用量/令牌数非负约束。

安全顾问仍有以下提示，不能把它们全部当成已经消失：

1. 13 个 RLS 已开启但无客户端策略的服务端表：没有为清除提示而开放读取。
2. 公开或登录用户可执行的 SECURITY DEFINER 函数：逐项检查了相关 OAuth、共享、协作者及管理接口的授权条件；保留必要的协议入口，未一刀切撤销导致登录失效。
3. 泄露密码保护仍未启用。本轮未擅自改变订阅或付费安全配置。[官方说明](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)。

仍需独立验证的范围：真实 iOS/Safari 与实体 Passkey 验证器、Windows Bridge 安装及开机行为、真实多地区 Cloudflare/R2/DO 故障注入、长时间负载与内存上限、独立 `chat.qsseda.com` 的完整端到端协议、付费链路全部业务路径，以及全站每种主题组合的人工可读性检查。R2/DO 的并发测试使用确定性替身，不能冒充真实云端事故演练。

旧客户端在不提交 revision 时会被明确拒绝保存，这是防止静默覆盖所需的兼容性改变；页面应提示保留/下载本地源码后刷新。不要通过删除版本检查或自动重试旧全文来消除 409/428。

部署回滚只回滚代码，不回滚数据。不得自动撤回 PKCE 安全迁移，也不得用旧源码覆盖已产生的新文件、删除标记或协作状态。任何回退都需先核对数据格式和客户端保存契约。
